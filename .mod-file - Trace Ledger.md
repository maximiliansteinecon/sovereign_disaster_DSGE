## 2. The four divergences

### 2.1 Eq (27): $e^{-2\mu}$ where Appendix C has $e^{-\mu}$ — a real bug, and the CHANGELOG's own "fix" caused it

```matlab
Ne = sigma_e*exp(-muz)*( RK*Qtob(-1)*k(-1) - RS(-1)*(Qtob(-1)*k(-1) - Ne(-1)) ) + iotae;
```

The `.mod` header records this as a fix applied on the reasoning that B.18
"explicitly states factor $\Gamma_t^{-1}$ applied to the whole bracket,
exactly mirroring eq (27)/B.23's bank net-worth structure." Both halves of that
argument are right about B.18 and B.23 and wrong about this equation, because
the two equations do **not** have the same structure.

B.18 is written in $k^n_t\equiv K_t/z_{t-1}$. Deflating the level equation by
$z_t$:

$$\frac{Q_{t-1}K_t}{z_t}=Q_{t-1}k^n_t\frac{z_{t-1}}{z_t}=Q_{t-1}k^n_t\Gamma_t^{-1},
\qquad \frac{N^e_{t-1}}{z_t}=n^e_{t-1}\Gamma_t^{-1},$$

so $\Gamma_t^{-1}$ is common to the whole bracket. Correct.

But the `.mod`'s `k(-1)` is **not** $k^n_t$. Eq (14) makes `k` the end-of-period
stock deflated by its own trend, so `k(-1)` $=K_t/z_t=k_t=e^{-\mu}k^n_t$. It
already carries one $\Gamma^{-1}$. The `.mod` knows this — eq (28) writes
`Qtob*exp(muz)*k` precisely when it wants $k^n$. Eq (27) does not.

Substituting `k(-1)`$=e^{-\mu}k^n_t$ into the coded equation:

$$n^e_t=\sigma^e\Bigl[R^K_te^{-2\mu}Q_{t-1}k^n_t
-R^S_{t-1}\bigl(e^{-2\mu}Q_{t-1}k^n_t-e^{-\mu}n^e_{t-1}\bigr)\Bigr]+\iota^e,$$

against B.18's $e^{-\mu}$ on all three terms. The lagged net-worth term is
right; the two capital terms carry the trend factor twice.

B.23 has no such problem because `QS(-1)`, `QbB(-1)` and `Nb(-1)` are all
deflated by their own date's trend, with no $k^n$ anywhere. **Eq (35) is
correct and eq (27) is not, for exactly the reason the two look alike.**

**Why nothing caught it.** `iotae` is calibrated residually from the same
expression, so the steady-state residual is identically zero. Eq (27) has no
leads, so it cannot touch the Blanchard–Kahn pencil — the CHANGELOG's note that
"eigenvalues are unaffected" is correct and is not evidence of correctness.

**Two equivalent fixes.** Either make $k^n$ explicit,

```matlab
Ne = sigma_e*exp(-muz)*( RK*Qtob(-1)*exp(muz)*k(-1) ...
     - RS(-1)*(Qtob(-1)*exp(muz)*k(-1) - Ne(-1)) ) + iotae;
```

or cancel it algebraically, which is the pre-"fix" form:

```matlab
Ne = sigma_e*( RK*Qtob(-1)*k(-1) ...
     - RS(-1)*(Qtob(-1)*k(-1) - exp(-muz)*Ne(-1)) ) + iotae;
```

The second is what the file had before 2026-07-29. **Revert it**, and add a
comment saying why the eq-(35) analogy does not carry over, so it is not
"fixed" again.

`iotae` must move with it, to match C.28
$\iota^e=\bar n^e(1-\sigma^ee^{-\mu}\bar R^S)-\sigma^e(\bar{\tilde R}^K-\bar R^S)\bar k$:

```matlab
iotae = Ness - sigma_e*( RKss*kss - RSss*(kss - exp(-muz)*Ness) );
```

Effect: a factor $e^{-\mu}=0.997$ on the $\sigma^e(\bar{\tilde R}^K-\bar R^S)\bar k$
term. Small in level, but it shifts $\iota^e$ and therefore the entrepreneur
block's whole calibration, and right now **Appendix C.28 is not what the code
computes** — which is the thing a supervisor will check first.

### 2.2 Eq (10): the `.mod` implements the Fisher equation A.1.7 rules out

```matlab
Q = pi(+1)/r;    % (6) deposit / risk-free Euler (Fisher)  (A.1.3)
```

Dynare reads this as $\mathbb{E}_t[\mathcal{M}_{t,t+1}]=\mathbb{E}_t[1+\pi_{t+1}]/(1+r_t)$,
i.e. $R^f_t=(1+r_t)/\mathbb{E}_t[1+\pi_{t+1}]$ — the textbook approximation.
B.30 and A.1.7 state
$\mathbb{E}_t[\mathcal{M}_{t,t+1}(1+r_t)/(1+\pi_{t+1})]=1$, and A.1.7 says in as
many words that the approximate form "is therefore not used", giving the
covariance and Jensen conditions under which the two differ.

Both gaps are second-order-and-above, so at the third order this thesis targets
they are live. The steady state is unaffected (§2.4 of the Appendix C ledger
explains why), which is why this has survived.

`Fisher_Taylor_Replacement_Draft.md` already contains the replacement. It needs
a `CE`-style auxiliary carrying the product under one expectation:

```matlab
% auxiliary: FI_t = E_t[ M_{t,t+1} / (1+pi_{t+1}) ]
FI = Q_realised_over_pi;   % see draft
r  = 1/FI;
```

Not a one-line change. Until it is made, **the tag on eq (10) is also wrong**:
it points at A.1.3, the deposit Euler, which is separately implemented by
eqs (11)–(12). Eq (10) is only the Fisher relation.

### 2.3 Eqs (22), (23), (32), (33): expectations factored into products of expectations

Four equations write $\mathbb{E}_t[X]\cdot\mathbb{E}_t[Y]$ where the appendix
has $\mathbb{E}_t[XY]$:

| eq | code | appendix |
|---|---|---|
| (22) | `X1 = y*mc + zeta*Theta*X1(+1)*pi(+1)^upsilon` | $\xi_{1t}=y_tmc_t+\zeta\mathbb{E}_t[\mathcal{M}\Gamma_{t+1}(1+\pi_{t+1})^\nu\xi_{1,t+1}]$ |
| (23) | `X2 = y + zeta*Theta*X2(+1)*pi(+1)^(upsilon-1)` | B.11, same structure |
| (32) | `etaB = Q*OmB(+1)*((1-phi)*RS + phi*Rb(+1) - Rd)` | $\eta^b_t=\mathbb{E}_t[\mathcal{M}\Omega^b_{t+1}\bar R^{ex}_{t+1}]$ |
| (33) | `nuB = Q*OmB(+1)*Rd` | B.21b, same |

`Theta` and `Q` are dated-$t$ variables, so Dynare factors them out and the
covariance terms $\mathrm{Cov}_t(\Theta,\xi_{1,t+1}\pi_{t+1}^\nu)$ and
$\mathrm{Cov}_t(\mathcal{M},\Omega^b\bar R^{ex})$ are dropped.

**This is defensible and I would keep it** — carrying four more auxiliaries
would cost more conditioning than it buys, and the same device is already used
correctly for `CE`. But it is not free: the dropped covariance in (32) is
exactly the channel through which disaster risk moves the bank's franchise
value, which is the paper's mechanism. At first order it vanishes; at third
order it does not.

**Two things to do.** State it in Appendix B where B.21a is introduced, as an
implementation note with its error order. And, since it is cheap, run the
`etaB`/`nuB` pair once with a `CE`-style auxiliary to bound the size of what is
being dropped — if the GIRF for `lev` moves by less than a basis point you can
say so in a footnote and the objection is closed permanently.

### 2.4 The $\psi$ transformation: the thesis and the code use different EIS

```matlab
psi = 1 - (1-psitilde)/(1+varpi); % Old Comment - is it actually true? has no
                                  % counterpart in the thesis, which defines psi
                                  % directly the inverse EIS. It yields psi = 1.3003, not 2.
```

Your own comment is the right question and it is still open. With
$\tilde\psi=2$ and $\varpi=2.33$ this gives $\psi=1.3003$, so the model runs an
EIS of $1/1.3003=0.769$ while the thesis text and calibration table say the
inverse EIS is 2, i.e. EIS $=0.5$. IS2017's main scenario is EIS $=0.5$.

This is not a small difference. $\psi$ enters $\bar Q^f$, $\bar R^f$, $\Theta$,
the value function and the sign of the $\beta(\theta_t)$ response to a disaster
shock — which is the result IS2017 organise their paper around.

I believe this is Gourio's reparameterisation for a Cobb–Douglas
consumption–leisure bundle, where the curvature over the bundle differs from
the curvature over consumption alone by the factor $(1+\varpi)$ — but **I
cannot confirm it from the material here and you should not take my word for
it.** Check Gourio (2012) directly, and check whether IS2017's replication code
applies the same transformation before calibrating $\tilde\psi$.

Three outcomes, all requiring an edit somewhere:

1. The transformation is Gourio's and IS2017 use it too → keep the code,
   document the mapping in Appendix A next to the utility function, and correct
   the calibration table to report $\tilde\psi=2$ as the input and
   $\psi=1.3003$ as the implied bundle curvature, with EIS $=0.769$.
2. The transformation is Gourio's but IS2017 calibrate $\psi$ directly → the
   code and IS2017 are not comparable and the $\psi$ line should go.
3. It is a leftover → delete the line, set $\psi=\tilde\psi=2$, **re-run the
   entire steady state and every result.**

Until this is settled, the calibration table cannot be finalised, so it belongs
ahead of the Appendix C rewrite in priority order despite being a Chapter 5
item.

## 5. `run_thesis_model.m`: two mislabelled result rows

Both in `local_steady_state_table`, both propagate into
`table_steady_state.csv` and from there into the Results chapter.

**Row 3, `'Sovereign spread (raw, ann. bps)'`**, computes `10000*ss(jSpread)`.
That is the **quarterly** gross spread in basis points, not annualised. The
printed 85.08 is 0.851% per quarter, roughly 3.4% annualised. Either relabel
the row "quarterly bps" or multiply by 4 — but note that if you annualise, the
Appendix C figure at L3700 has to move with it.

**Row 5, `'Entrepreneur premium E[R^K]/R^S'`**, computes `ss(jRK)/ss(jRS)`.
The `.mod`'s `RK` is the **disaster-free** $\tilde R^K$, so this is
$\bar{\tilde R}^K/\bar R^S=\texttt{premE}/(1-\bar\theta\Delta^k)=1.004990$ —
which is what the file prints. The *expected* premium, which is the calibration
target, is $\mathbb{E}[\bar R^K]/\bar R^S=\texttt{premE}=1.0030$.

The row reports the realised premium under the expected premium's name, and the
gap between them (~20 bps annual) is exactly the $\mathcal{K}(\bar\theta)$
wedge Appendix C is careful to keep separate. Fix:

```matlab
Mtab(5,c1) = (1 - thetass*Deltak) * ss(jRK)/ss(jRS);   % E[R^K]/R^S
```

or add a second row and report both, which is arguably more informative.

**Also stale, harmless but misleading:** three comments (lines 248, 308, 324)
say the leverage target is 4.0; `levss = 6`. Since `lambdadiv` is derived from
`levss`, anyone reading the comments will reconstruct the wrong $\theta^b$.
